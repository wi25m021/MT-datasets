# MT-datasets

Data for the master thesis **"Beyond the Cloud: Evaluating On-Device LLMs for Text Processing on
Android"** — Taras Gladun, Master Information Systems Management, FH Technikum Wien.

The thesis develops a vertical prototype artefact in the form of an Android application for
confidentiality-sensitive legal text processing and comparative evaluation of multiple LLM
backends: LiteRT-LM with an open Gemma-family model, and AICore via the ML Kit Prompt API using Gemini
Nano. A fixed set of legal
documents and questions is used to create reproducible workloads for the benchmark and predictive
modeling. This repository describes and provides all data the thesis uses.

## Datasets

| # | Dataset | Role in the thesis | Type | Access | Folder |
|---|---|---|---|---|---|
| 1 | CUAD v1 (legal contracts + expert labels) | source of the legal documents and questions | secondary, public | open, CC BY 4.0 | [`CUAD_v1/`](CUAD_v1/) |
| 2 | Measurement data | per-request metrics; training and evaluation data for the predictive models and the router | primary, generated by the prototype | open, in this repository | [`Telemetry/`](Telemetry/) |

No further datasets are required for the research questions.

## 1. CUAD v1 — Contract Understanding Atticus Dataset

- **Content:** 510 commercial legal contracts with more than 13,000 expert labels in 41 clause
  categories. Files: 510 contracts as PDF and as TXT, `master_clauses.csv` (labels and answers per
  contract), `CUAD_v1.json` (SQuAD-style question/answer format), 28 Excel files (clauses per
  category), `CUAD_v1_README.txt` (original description).
- **Source:** The Atticus Project — Zenodo record https://doi.org/10.5281/zenodo.4595826 (file
  `CUAD_v1.zip`), project page https://www.atticusprojectai.org/cuad, code
  https://github.com/TheAtticusProject/cuad
- **Licence:** CC BY 4.0 (https://creativecommons.org/licenses/by/4.0/)
- **In this repository:** unchanged, extracted copy of `CUAD_v1.zip` (downloaded 21.11.2026).
- **Citation:** D. Hendrycks, C. Burns, A. Chen and S. Ball, "CUAD: An Expert-Annotated NLP Dataset
  for Legal Contract Review," NeurIPS 2021 Datasets and Benchmarks Track.
- **Why suitable:** real legal contracts represent the confidentiality-sensitive documents of the
  use case, while being public, so the workloads are reproducible. Contract lengths vary widely,
  which allows deliberate variation of prompt length (main workload feature). Expert labels provide
  expected answers.

## 2. Measurement data

Generated on Android and logs telemetry inside CSV.

- **Per-request metrics:** time to first token, tokens per second, end-to-end response latency,
  peak resident memory usage, battery consumption (battery delta and energy from current/voltage
  sampling) and thermal status/headroom obtained through Android system APIs — together with the
  workload (task type, prompt length) and the device state at start and end of each request
  (battery level, thermal state, memory). 60 columns per row; full data dictionary, units and
  collection protocol: [`Telemetry/DATA.md`](Telemetry/DATA.md).
- **Collection protocols:** `smoke` (pipeline check), `ramp` (both backends alternating per
  prompt, from cool to hot device state, then cooldown), `sustained` (one backend, 20 min).
  Conditions: on battery, airplane mode, fixed screen brightness, phone on a stand without case.
- **Layout:** one folder per session, `Telemetry/sessions/<session_id>/` (pipeline checks and
  pilot runs: `Telemetry/pilot/`):

  | File | Content                                                                          |
  |---|----------------------------------------------------------------------------------|
  | `session.json` | device, software and model versions, protocol parameters, conditions, end reason |
  | `runs.csv` | one row per request (main table)                                                 |
  | `outputs.csv` | model answer and expected CUAD answer per request                                |
  | `thermal.csv` | device state once per second for the whole session                               |
  | `traces/<block_id>.csv` | current, voltage, and memory every 100 ms (raw data behind the energy values)    |

- **Format:** CSV (UTF-8, comma-separated, `.` as decimal separator, empty field = missing value)
  and JSON.
